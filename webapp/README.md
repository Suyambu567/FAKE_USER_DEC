# Fake User Detection — Web App

A static web app. HTML, CSS and vanilla JavaScript only: **no backend, no API, no
framework, no build step.** Detection runs in the browser.

---

## Run it

The page fetches `model/model.json`, and browsers block `fetch` over `file://`, so
it needs a local HTTP server. Any of these work — no installation beyond what you
already have:

```bash
cd webapp

python3 -m http.server 8451 --bind 127.0.0.1      # Python 3
npx serve -l 8451                                  # Node
php -S 127.0.0.1:8451                              # PHP
```

Then open **<http://127.0.0.1:8451>**.

> Opening `index.html` directly by double-clicking will show
> *"Could not load the model"*. That is the `file://` restriction, not a bug.

## How it works

```
index.html
   │
   ├── js/model.js      the exported scikit-learn pipeline, evaluated in JS
   ├── js/features.js   user-ID validation, demo profiles, form parsing
   └── js/app.js        UI wiring only — no detection logic
                        │
                        └── model/model.json   scaler + TF-IDF + 60 trees (256 KB)
```

**Nothing was reimplemented.** `ml/export_to_json.py` serialises the *already
fitted* pipeline — the same `StandardScaler` means, the same TF-IDF vocabulary and
idf weights, the same tree splits — and `model.js` evaluates them. The maths in
the browser is the maths scikit-learn ran; only the language differs.

That equivalence is tested, not assumed:

```bash
node test/parity.mjs      # 302 cases vs Python; max probability gap 6.3e-7
node test/logic.mjs       # validation, demo profiles, robustness, explanations
```

`test/cases.json` is regenerated from the Python model whenever the model changes.

## What the app can and cannot do

**It cannot fetch a real Instagram profile.** No static page can:

* Instagram's Graph API only exposes accounts that have authorised your app — it
  cannot look up an arbitrary username.
* Scraping the site is blocked by the browser's same-origin policy and violates
  Instagram's Terms of Service.
* There is no server here to proxy either.

So the app works in two modes, and always says which one produced a result:

| You provide | What happens |
|---|---|
| A user ID only | A **deterministic demo profile** is generated from the ID. The result card carries a "Demo data" banner and the generated numbers are shown in full. |
| A user ID **and** the profile statistics | A real analysis of the numbers you entered. No banner. |

The second mode is the useful one. Fill in the profile's real followers,
following, posts, engagement rate, average likes and comments, account age and
bio, and the verdict reflects that actual data.

## Reading the result

* **Verdict** — Real User ✅ or Fake User 🚨.
* **Confidence** — the model's probability for the class it chose. Below 60% the
  app says so: a binary classifier near 50% is expressing no opinion, whatever
  label it prints.
* **Why** — each input is re-scored with that value replaced by a typical
  profile's, and the shift in probability is reported. `↑ 8.4 pts` means removing
  that value would drop the verdict's probability by 8.4 points, so it is one of
  the things driving the answer.
  Per-profile ablation is used rather than the model's global feature
  importances, because importances describe the *model* while this describes
  *this profile* — which is what "why?" actually asks.
* **About this model** — version, training data, accuracy **next to** the
  always-guess baseline, and any quality warnings recorded at training time.

## The model shipped here

Trained on `data/synthetic_signal.csv`, generated by
`backend/ml/generate_dataset.py`.

| | |
|---|---|
| Algorithm | RandomForest (60 trees, depth 9) + TF-IDF on bio + scaled numerics |
| Accuracy | **0.9342** |
| Always-guess baseline | 0.6312 |
| Lift over baseline | **+0.303** |
| Cross-validated accuracy | 0.9367 ± 0.0028 |
| Artifact | 256 KB (70 KB gzipped) |

**This is synthetic data.** The generator encodes how fake engagement actually
behaves — mass-following, bot likes without comments, young accounts, promo bios —
but it is not real Instagram. The model has learned those rules, and that caveat
is carried in `model.json` and shown in the "About this model" card.

The dataset originally shipped with this project (`website/dataset.csv`) is
**unusable**: `data/app.py` assigns `Account Type` with `np.random.choice`, so the
labels are independent of every feature. A model trained on it scores 0.523
against a 0.508 baseline. See `docs/AUDIT.md` §11.1.

### Retraining

```bash
cd ../backend
.venv/bin/python -m ml.train --dataset <your.csv> --out artifacts/web \
    --n-estimators 60 --max-depth 9 --min-samples-leaf 30
.venv/bin/python -m ml.export_to_json \
    --model artifacts/web/model.joblib \
    --meta  artifacts/web/model_meta.json \
    --out   ../webapp/model/model.json
cd ../webapp && node test/parity.mjs
```

Keep the forest small: every node ends up in the JSON the browser downloads.
60 trees at depth 9 is 256 KB; 200 trees at depth 14 would be several megabytes
and a slow first load on mobile data.

Only `RandomForest`, `ExtraTrees`, `DecisionTree`, `LogisticRegression` and
`LinearSVC` can be exported. Gradient-boosted models (XGBoost, LightGBM,
HistGradientBoosting) have no JSON exporter here — the tree format differs.

## Browser support

Modern evergreen browsers: Chrome/Edge 111+, Firefox 113+, Safari 16.4+.
The floor is `color-mix()` in CSS and `String.matchAll` with unicode property
escapes in JS. No polyfills, no transpilation.

Fully responsive from 320 px; touch targets are at least 44 px; the theme follows
the OS and can be toggled. `prefers-reduced-motion` is respected.

---

## Privacy

After `model.json` loads, the page makes no network requests. Everything you type
stays in the tab — there is no server to send it to.
